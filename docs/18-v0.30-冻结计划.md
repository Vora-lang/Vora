## 3. 详细方案

### 3.1 T1：`Obj` → `class`

#### 为什么是 `class` 而不是小写 `obj`

实测结论（在 `std/`、`examples/`、`tests/` 范围统计标识符占用）：

| 候选 | 既有标识符冲突 | 说明 |
|---|---|---|
| `obj` | **28 处** | 含 `let obj = ...` 这类最自然的实例变量命名；把 `obj` 变成关键字会破坏它们 |
| `class` | **8 处，且全部位于注释或字符串字面量内**（如 `// character class`、`print("=== 7. Method from intermediate class ===")`） | 关键字不影响注释/字符串，故**实际破坏 0 处** |

另外三点支持 `class`：

1. **契合语言自述身份**：项目原则第 3 条是「JS 语法 + Lua 简洁 + **Wren OOP**」，而 JS 与 Wren 的类声明关键字都是 `class`。
2. **`obj` 作为关键字有可读性缺陷**：全小写的 `obj` 读起来像实例变量名，而不是声明关键字；错误信息「Expected obj」也会让人困惑。
3. **冻结是最后一个免费的破坏性窗口**：若现在选 `obj`，日后几乎必然还要再改一次 `class`，等于付两次破坏性代价。

**与「类/封装设计仍在讨论」的关系**：那条讨论的是成员可见性/封装模型（`private`/`public`、静态成员、构造语义等）。本项只改**声明关键字**，不预设可见性模型，因此不与该讨论冲突。若讨论最终会改变构造本身的形态（例如拆成 `class` + `interface`），`class` 仍是其中可实例化那一个的自然名字。

#### 影响面清单（实测计数）

| 位置 | 数量 | 处理 |
|---|---|---|
| `src/lexer/lexer.cpp:17` `{"Obj", TokenType::OBJ}` | 1 | 改关键字串 |

### 3.2 T2：`match` 无匹配臂改为运行时错误

#### 现状

`src/vm/compiler_expr.cpp:1334`：

```cpp
if (isLast && !hasWildcard) {
    emitByte(static_cast<uint8_t>(OpCode::OP_NULL));   // ← 静默返回 null
}
```

即 `let r = match 99 { 1 => "one" }` 得到 `r = null`，无任何提示，`null` 会一路传播到很远才炸（评审 §3.8 实测 A3b）。

#### 为什么必须处理（而不是记为「接受现状」）

这是**唯一一条不属于「风格/一致性」而属于「静默错意」的 P2**，直接违反项目原则第 7 条「不可静默：绝不允许语法合法但语义非所见」。其余 P2 项最多是「现在能忍」，这一条是「会静默产生错误结果」，性质与 P0 同级。

#### 方案（已定）

把 `emitByte(OP_NULL)` 改为**抛出可捕获的运行时错误**：

- 先弹出已匹配失败的被匹配值（当前位置前一条已是 `OP_POP`，栈是平衡的，直接构造错误值并 `OP_THROW` 即可）。
- 错误信息建议包含源行号，并尽量带上未匹配的值（若要在信息里带值，需保留被匹配值不弹出，两者取其一——建议带上值，诊断价值更高）。
- 必须是**可被 `try/catch` 捕获**的普通运行时错误，不要做成不可捕获的致命错误。

#### 备选（列出但不推荐）

编译期强制「必须有 `_` 臂」。缺点是 `match flag { true => "a", false => "b" }` 这类已经很完整的匹配会被迫加一条冗余 `_` 臂；且动态语言无法真正判定穷尽性。

#### 影响与验证

- **破坏性**：现有依赖「无匹配返回 null」的代码会开始抛错 —— 必须写入 BREAKING。
- 正例：带 `_` 臂的 match 行为完全不变（`examples/43-match.va` 等）。
- 反例：无 `_` 臂且未匹配 → 抛错；在 `try` 内可被捕获；错误信息含行号。
- 全量回归。

### 3.3 T3：尾随逗号

实测当前 5 处全部报错（错误信息为实测值）：

| 位置 | 现状错误 | 目标 |
|---|---|---|
| 数组字面量 `[1, 2,]` | `Unexpected token: ]` | 允许 |
| 字典字面量 `{x: 1,}` | `Unexpected token: }` | 允许 |
| 调用实参 `f(1, 2,)` | `Unexpected token: )` | 允许 |
| 形参表 `func f(a, b,)` | `Expected parameter name` | 允许 |
| 解构模式 `let [p, q,] = ...` | `Expected binding pattern` | 允许 |

要求：

- **纯增量**：不得改变任何现有合法代码的含义。
- 反例必须仍报错：`[1,,]`（连续逗号）、`[1, ]` 之后的非法 token、`f(, 1)`（前导逗号）。
- 字典字面量需与「对象字面量简写」规则协同（`{x,}` 应等价于 `{x}`）。
- `vora fmt` 往返幂等。
- EBNF 产生式恢复可选尾随逗号（此前因未实现而移除了该声明，现在实现后要改回来）。

### 3.4 T4：CHANGELOG 标注 `BREAKING`

`docs/00-roadmap.md` 的 Phase 1 出口标准明文要求「所有破坏性变更在 `CHANGELOG.md` 标注 `BREAKING`」，目前一条都没有。需集中列为 `## Breaking changes` 小节，并逐条写清「旧行为 → 新行为 → 用户需要怎么改」：

| # | 变更 | 旧 → 新 |
|---|---|---|
| 1 | Go 式 ASI | `let b = a` 换行 `-1`：加法表达式 → 两条语句 |
| 2 | 三元优先级 | `a \|\| b ? c : d`：`a \|\| (b?c:d)` → `(a\|\|b)?c:d` |
| 3 | `import` 路径校验 | 含 `-` 的路径静默派生绑定名 → 编译报错（需 `as` 别名或 `from ... import`） |
| 4 | `not` 成为关键字 | 可作标识符 → 保留字 |
| 5 | `\$` 插值转义 | `"\${x}"`：`\5`（反斜杠+插值）→ 字面量 `${x}` |
| 6 | 标签 `break`/`continue` | `break x`：`break` + 独立语句 → 标签引用（不存在则编译报错） |
| 7 | **`Obj` → `class`（T1）** | 关键字改名 |
| 8 | **`match` 无匹配臂（T2）** | 静默返回 `null` → 抛运行时错误 |

## 4. 顺序与依赖

```
T1 (Obj→class) ──┐
T2 (match 报错) ─┼─→ T3 (尾随逗号) ─→ T4 (BREAKING) ─→ T5 (版本+tag)
T6 (文档收尾) ────┘
T7 (根文件) —— 独立，随时可做
```

理由：

1. **T1、T2 必须先落地**，因为它们会改动 EBNF/USER_GUIDE/CHANGELOG 的同一批位置；先做可避免文档改两遍。
2. **T3 可与之并行**（不同代码路径），但放其后可让全量回归只跑一次关键轮次。
3. **T4 必须在 T1/T2 之后**，否则 BREAKING 清单不完整。
4. **T5 最后**，tag 一旦打出即代表冻结生效。
5. **T6 贯穿**：3.5/P2 的措辞可先写，计数修正与 3.9 注释随 T1/T2 一起提交。
