## 1. 元语法约定

| 记号 | 含义 |
|---|---|
| `=` | 定义 / 规约为 |
| `\|` | 或（alternation） |
| `{ … }` | 出现 0 次或多次 |
| `[ … ]` | 出现 0 次或 1 次 |
| `( … )` | 分组（precedence 控制） |
| `"…"` | 字面 token（与 lexer 的 token 对齐） |
| `?? … ??` | 解释性注释 |
| `ε` | 空（不产生任何 token） |

终结符（terminals）是大写 token 名称或字面字符串，对应 `src/lexer/token.h::TokenType` 枚举值。

非终结符使用小写驼峰（`statement`, `expression`, `identifier`, …）。

## 2. 词法（Lexical）

### 2.1 标识符（identifier）

```
identifier      = ( letter | "_" ) { letter | digit | "_" }
letter          = "A"…"Z" | "a"…"z"
digit           = "0"…"9"
```

合法：`x`, `_tmp`, `count2`, `__init__`。
非法：`1abc`, `foo-bar`, `foo.bar`, `foo$bar`。

> ✅ P0 #4 修复后这同一规则也在 `Parser::isLegalIdentifier()` 里使用，确保 `import "path"` 的派生 binding 名也满足这套规则。

### 2.2 关键字

保留关键字（不能作为标识符）：

```
let, const, func, return, if, else, while, do, for, in,
class, this, super, break, continue, try, catch, finally, throw,
import, export, as, from,
yield, async, await, match, defer,
true, false, null
```

### 2.3 字面量

```
numberLiteral   = digit { digit } [ "." digit { digit } ]
                | digit { digit } "."  ?? 用于已识别的科学记数法由 lexer 规整，不在本 EBNF 中展开

stringLiteral   = '"' { stringChar } '"' | "'" { stringChar } "'"
stringChar      = escapeSequence | ( any-character-except-quote-backslash-newline )
escapeSequence  = "\\" ( "n" | "t" | "r" | "\\" | '"' | "'" | "$" )

interpolation   = "${" expression "}"   ?? 见 §6.5
```

> 字符串内 `${ ... }` 任意 expression。`\$` 转义掉插值语义（输出字面 `$`），**2026-09 Phase 1 起已实现**：
> 词法层把 `\$` 记为带内标记（`kEscapedDollar`），编译器据此不视为插值起点并在产出常量时还原为 `$`；
> 常量折叠与 formatter 均已同步（`vora fmt` 往返不改语义）。
> ⚠ `"\\${x}"`（转义反斜杠 + 插值 → `\5`）与 `"\${x}"`（字面 `${x}`）不同，因为词法层先解析 `\\`。

### 2.4 运算符 token（列在 precedence 升序，见 §6）

| precedence | token | 名字 | 结合性 |
|---|---|---|---|
| 1 | `\|\|`, `??`, `?:` | 逻辑或 / 空合并 / 三元 | 左 / 左 / 右 |
| 2 | `&&` | 逻辑与 | 左 |
| 3 | `\|` | 按位或（match 分支内为或模式分隔） | 左 |
| 4 | `^` | 按位异或 | 左 |
| 5 | `&` | 按位与 | 左 |
| 6 | `==`, `!=` | 等值 | 左 |
| 7 | `<`, `<=`, `>`, `>=`, `in` | 关系 / 成员 | 左 |
| 8 | `<<`, `>>` | 移位 | 左 |
| 9 | `+`, `-` | 加减 | 左 |
| 10 | `*`, `/`, `%` | 乘除模 | 左 |
| 11 | `**` | 幂 | 右 |
| — | `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `**=` | 赋值 | 右 |

> P1-F（2026-09）起本表数值与 `parser.cpp getPrecedence()` 一一对应；复合赋值（含 `**=`）为右结合，见 §6 末尾。

**未实现 / 保留**（一元前缀见 §6.6）：无。

## 3. 顶层 / 程序

```
program         = { topLevelStatement } EOF

topLevelStatement =
      letDecl
    | constDecl
    | funcDecl      [ "async" ]
    | classDecl
    | importDecl
    | fromImportDecl
    | exportDecl
    | statement        ?? 见 §4
    | ";"              ?? 空语句
```

> v1.0 不允许 `module foo` / `package bar` 等顶层命名修饰。模块名通过 `import "path"` 自然出现。

## 4. 语句（Statement）

```
statement       = exprStmt
                | blockStmt
                | labeledLoop
                | ifStmt
                | whileStmt
                | doWhileStmt
                | forStmt
                | returnStmt
                | breakStmt
                | continueStmt
                | tryStmt
                | throwStmt
                | deferStmt
                | letDecl
                | constDecl
                | funcDecl
                | classDecl
                | importDecl
                | fromImportDecl
                | exportDecl
                | ";"            ?? empty statement (合法但通常不必要)

exprStmt        = expression
```

语句终止：

- 显式 `;`（可选）。
- **ASI（自动分号插入，Go 风格，P0 #1）**：当且仅当
  1. parser 处于 statement-level 表达式上下文（`Parser::asiDepth_ > 0`，由 `Parser::expression()` 进入时设定），且
  2. 当前不在配对完的 `(` … `)` 或 `[` … `]` 内（`Parser::parenDepth_ == 0`，由 `match()` 在配对括号时维护），且
  3. 下一个 token 的行号 **严格大于** 当前 token 的行号

  这时 `parsePrecedence()` 的 infix 循环提前 break，等价于把那个换行当成一个 `;`。详细代码：`Parser::parsePrecedence()` 中的 `asiDepth_ > 0 && parenDepth_ == 0 && peek().line > previous().line`（`src/parser/parser.cpp:2465`）。

### 4.1 控制流

```
ifStmt          = "if" "(" expression ")" statement [ "else" ( ifStmt | statement ) ]
whileStmt       = "while" "(" expression ")" statement
doWhileStmt     = "do" statement "while" "(" expression ")" ";"
forStmt         = cFor | forIn
cFor            = "for" "(" [ forInit ] ";" [ expression ] ";" [ expression ] ")" statement
forInit         = letDecl | expression
forIn           = "for" ( forBinding | "(" forBinding ")" ) "in" expression statement
forBinding      = identifier
                | arrayBinding | objectBinding         ?? 解构绑定暂仅 for-in 支持

> ✅ P1-H 后 `for (x in xs) { ... }` 与 `for ([a,b] in pairs) { ... }` 也接受括号 for-in 形式。`Parser::cForStatement()` 顶部用 2-token lookahead + brace-aware scan 检测该形式，避免与 C-style for 冲突。
labeledLoop     = identifier ":" ( whileStmt | doWhileStmt | forStmt )
breakStmt       = "break" [ identifier ] ";"
continueStmt    = "continue" [ identifier ] ";"
```

> **标签循环（syntax-review #2.8，Phase 1 最后一项）**：`outer: for i in [...] { ... }` 为循环命名，
> `break outer` / `continue outer` 从任意嵌套深度跳到**指定**那一层。
>
> - 标签**只能挂在循环上**：`x: if (...) { }` 是编译期错误。没有 `goto`，非循环标签不可能成为跳转目标，
>   所以直接拒绝而不是"能写但没用"。
> - 循环前的 `identifier ":"` 在语句起始位置此前不是合法语法（旧版报 `Unexpected token: :`），
>   故 `Parser::statement()` 顶部用 `peekNext()` 做 2-token lookahead 无歧义（`parser.cpp:167`）。
> - `break` / `continue` 后的标识符**仅当与关键字同一行**时才视为标签，与 §4 的 ASI 规则一致：
>   `break` 换行后跟 `foo()` 仍是两条语句。
> - 指向不存在的标签、以及同一嵌套链上重复的标签，都是**编译期错误**；不相邻的两个循环可以重名。
>
> ⚠ **兼容性变化**：旧版同一行的 `break <标识符>` 是合法的，被解析为两条语句且后一条恒为死代码
> （`break` 无条件转移控制）。本项起它被解析为标签引用，于是这类写法会变成硬编译错误。
> 对 `tests/`、`examples/`、`std/` 全量 grep 确认无一处使用该写法。

### 4.2 异常 / 延期

```
tryStmt         = "try" blockStmt [ "catch" "(" identifier ")" blockStmt ] [ "finally" blockStmt ]
                ?? at least one of catch / finally 必须存在
throwStmt       = "throw" expression ";"
deferStmt       = "defer" statement ?? 执行推迟到当前作用域退出
```

### 4.3 函数 / 对象

```
funcDecl        = [ "async" ] "func" identifier "(" [ parameters ] ")" [ returnType ] blockStmt
returnType      = ":" typeExpr               ?? v1.0 typeExpr 留 reserved，目前解释为可省注释
parameters      = parameter { "," parameter }
parameter       = identifier [ "=" expression ]       ?? 默认参数
                | "..." identifier                    ?? rest param —— 仅在 class 方法体内合法（见 §5）
```

```
classDecl         = "class" identifier [ ":" identifier ] blockStmt
                ?? 父类目前仅支持单继承（多继承 C3 线性化由运行时而非类型系统表达）
objBody         = { objMember }
objMember       = "func" identifier "(" [ parameters ] ")" blockStmt   ?? 方法
                | "this" "." identifier "=" expression ";"              ?? 字段初始化
```

### 4.4 变量

```
letDecl         = "let" bindingPattern [ "=" expression ] ";"
constDecl       = "const" bindingPattern "=" expression ";"
bindingPattern  = identifier
                | arrayBinding | objectBinding
```

> `let x`（无初始化）**自 2026-09 Phase 1 起接受**，绑定值默认为 `null`，
> 因此 `let x; if (c) { x = 1 }` 可用（先行评审曾标"保留"，现已按 §2.7 落地）。
> 带类型标注时行为等价于显式 `let x:T = null`——即标注的运行时转换照常生效，
> 数值类型得到零值（`let a:int` → `0`）。
> `const` 仍**必须**有初始化（无值的不可变绑定无意义）。

### 4.5 模块导入 / 导出

```
importDecl      = "import" stringLiteral [ "as" identifier ] ";"
fromImportDecl  = "from" stringLiteral "import" identifier { "," identifier } ";"
exportDecl      = "export" ( letDecl | constDecl | funcDecl | classDecl | "{" exportList "}" )
exportList      = identifier { "," identifier }
```

**派生 binding 名规则（P0 #4）**：

```
importBinding   = identifier   ?? alias 由 'as' 显式给出
                | basename( stringLiteral )   ?? 自动派生（无 'as' 时）
```

派生规则：`basename(s)` 是路径最后一个 `/` 或 `\` 之后的子串，**再**剥除尾部的 `.va`（如果有）。得到的字符串必须是合法 `identifier`（§2.1），否则报 parser error 并要求改写：

```
import "std/json"        →  alias  = "json"        ✅
import "math"            →  alias  = "math"        ✅
import "./foo"           →  alias  = "foo"         ✅
import "math.va"         →  alias  = "math"        ✅
import "foo-bar"         →  ERROR  (basename 含 '-')
import "./foo-bar"       →  ERROR
```

修复方向统一为：

```
import "foo-bar" as bar            ← 用 'as'
from "foo-bar" import thing1, ...   ← 用 'from...import'
```

> ✅ `from ... import a, b, ...` 不触发上面这套 basename 校验，identifier list 走显式 IDENT token，永远合法。

### 4.6 匹配（match）

```
matchExpr       = "match" "(" expression ")" "{" { matchArm } "}"
matchArm        = matchPattern { "|" matchPattern } "=>" ( matchExpr | blockOrExpr )
matchPattern    = literal | identifier | "_" | rangePattern
                ?? 注意：单一 matchArm 内的多个 matchPattern 必须同属一个 pattern kind
                ?? （全部 literal、或全部 range 等）。若混合，parser 报
                ?? `Mixed pattern kinds in or-pattern`。
rangePattern    = expression ".." expression | expression "..=" expression

?? 实现状态（v1.0）：or-pattern 已经走通 lexer → parser 路径；测试覆盖
?? 见 §8 表 `parser_match_or_pattern_*`（4 个 case：3 个 literal 串、
?? 2 alternative、长 alternation 5 个 literal、向后兼容 vanilla match）。
```

**无匹配臂的语义（2026-09 起）**：当没有任何臂匹配、且不存在通配符 `_` 臂时，
match **抛出可被 `try/catch` 捕获的运行时错误**，信息形如
`no match arm matched the value: <值>`，并带出 match 表达式所在行号。
空 match（`match x { }`）在**解析期**即报 `Match expression must have at least one arm`。

> 变更原因：早期版本此处静默产生 `null`，`null` 会一路传播到远离出错点的地方才失败
> （参见 `VORA_SYNTAX_REVIEW.md` §3.8）。按设计原则第 7 条「不可静默」，改为显式报错。
> 该行为属**破坏性变更**，见 `CHANGELOG.md` 的 Breaking changes。

## 5. 表达式（Expression）

```
expression      = ?? Pratt 主循环，按 §6 precedence 表爬升
```

### 5.1 一元前缀

```
unary           = ( "!" | "not" | "~" | "-" | "+" | "++" | "--" ) unary | primary
```

一元 `+` 是 identity 操作；常量折叠时 `+literal` 直接 emit constant 字面值，runtime 不 emit 任何 opcode（OP 无副作用，值已在栈上）。见 `src/vm/compiler_expr.cpp:288` visitUnaryExpr。

> `not` 是 `!` 的**别名**（2026-09，syntax-review #2.9）——同一个 `TokenType::NOT`，
> 因此优先级、结合性与语义完全一致。与 `and`/`or` 是 `&&`/`||` 的别名同理。
> ⚠ **与 Python 不同**：`not` 绑定**紧于**比较运算，`not x > 0` 解析为 `(not x) > 0`
> （通常报错 "Invalid operands for >"）。取反比较请写 `not (x > 0)`。这与 `!` 的行为一致。
> `~` 为按位取反（见 §6 / P1-F）。

### 5.2 后缀

```
postfix         = primary { postfixOp }
postfixOp       = "++" | "--" | "(" [ arguments ] ")" | "[" expression "]"
                | "." identifier | "?." ( identifier | "(" [ arguments ] ")" | "[" expression "]" )
                | [ "=" | compoundAssignOp ] expression                  ?? 仅当合法 l-value
```

**l-value**：仅 `variable`, `property access (obj.x)`, `index access (arr[i])` 可作赋值目标。

### 5.3 调用 / 参数（P0 #3 已 lock-in）

```
arguments       = argument { "," argument }
argument        = [ "..." ] expression                     ?? spread
                | identifier "=" expression                ?? named argument
```

**2-token 前瞻规则**：

- 在 call argument list 中遇到 `IDENTIFIER` 后紧跟 `=` —— 视为命名参数 `(name, value)`，**不**视为 assignment expression。
- 在 argument list 外（如 `let x = a = 5`），`a = 5` 仍是 assignment expression，两侧都被 lex 为对应 token。
- 形参列表（`func f(a, b = 2)` 的 `"b = 2"`）走另一套 `parameter` 规则（§4.3）。
- **顺序约束**：positional 必须排在 named 之前；positional-after-named 报 parser error 但 AST 仍然产生（不丢值）。

### 5.4 数组 / 字典字面量

```
arrayLiteral    = "[" [ expression { "," expression } ] "]"
dictLiteral     = "{" [ dictEntry { "," dictEntry } ] "}"
dictEntry       = identifier                                  ?? 简写 ⇒ {"name": name}
                | ( identifier | stringLiteral | expression ) ":" expression    ?? bare ident ⇒ string key
```

> **简写条目** `{x}` 等价于 `{x: x}`（2026-09 Phase 1 起，见 §2.7/#2.11）；
> 仅当标识符后紧跟 `,` 或 `}` 时才识别为简写，字典推导式与其它形式不受影响。

> ⚠ **尾随逗号当前不支持**：`[1, 2,]`、`{a: 1,}`、`f(1, 2,)`、`func f(a, b,)` 均报错
> （实测确认，2026-09）。本 EBNF 上方产生式已移除此前误标的可选尾随逗号；该项记入
> roadmap Phase 1 剩余清单。解构模式的 `[a, b,]` 同样不支持。

## 6. 运算符优先级与结合性

按 precedence **升序**（数值越小越松，即后绑）：

| 优先级 | 运算符 | 结合 | 含义 |
|---|---|---|---|
| 1 | `\|\|` | 左 | 短路或 |
| 1 | `??` | 左 | null-coalescing |
| 1 | `?` `:` | **右** | 三元条件（低于 `\|\|`：见下） |
| 2 | `&&` | 左 | 短路与 |
| 3 | `\|` | 左 | 按位或（P1-F；match 分支内为或模式） |
| 4 | `^` | 左 | 按位异或（P1-F） |
| 5 | `&` | 左 | 按位与（P1-F） |
| 6 | `==`, `!=` | 左 | 等值 |
| 7 | `<`, `<=`, `>`, `>=` | 左 | 关系 |
| 7 | `in` | 左 | 集合/字符串成员测试（返回 bool；与 Python 一致：`a + b in arr` = `(a + b) in arr`） |
| 8 | `<<`, `>>` | 左 | 移位（P1-F；算术右移，计数 ≥64 或 <0 时夹取，见 §7） |
| 9 | `+`, `-` | 左 | 加减 |
| 10 | `*`, `/`, `%` | 左 | 乘除模 |
| 11 | `**` | 右 | 幂 |

> ⚠ **位运算低于等值**（C/JS 同款陷阱）：`a & b == c` 解析为 `a & (b == c)`。位运算与比较混用时务必加括号。

> ✅ P0 #2 修复后 `?:` 与 `\|\|` / `??` 共用优先级 1。`\|\|` 是 left-associative，会先把左子表达式吃完，ternary 才从结果再包整体：
>
> ```
> a || b ? c : d    ===    (a || b) ? c : d
> a ? b : c || d    ===    a ? b : (c || d)
> a && b ? c : d    ===    (a && b) ? c : d     ?? AND prec 2，仍先 bound
> a ? b ? c : d : e ===    a ? (b ? c : d) : e  ?? 三元自身右结合
> ```

赋值（`=`, `+=`, `-=`, `*=`, `/=`, `%=`, `**=`）在 Pratt 中由 `parsePrecedence()` 内联处理；它们不进入 `getPrecedence()` 的级别表（不能与其它二元运算符自由组合），且均为右结合。

> ⚠ `**=` 的结果是 **float**，因为裸 `**` 本身就是 float 运算（`2 ** 3` → `8.0`）；`int` 变量经 `**=` 后变为 float。

### 6.1 ASI 与 precedence 的交互

Pratt 循环在 infix 入口检测 ASI：见 §4 末尾。**只有**当下一个 infix token 处于"新的语句行"且上下文为 statement-level 时，循环才提前退出。换言之：

- `f(a\n, b)` —— `(` 已开，`parenDepth_ = 1 > 0`，ASI 不触发，函数调用跨行 OK。
- `[1,\n2,\n3]` —— `[` 已开，同上，数组字面量跨行 OK。
- `let a = b\n- 1` —— top-level、paren=0、下一行号 > 当前行号，ASI 触发，`-1` 视为下一条语句。
